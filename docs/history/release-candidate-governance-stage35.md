# Stage 35 all-package release-candidate governance / 阶段 35 全包发布候选治理

Stage 35 replaces the single-package maintenance view with one machine-executable gate for all nine packable DeploySharp projects. `eng/pack/Test-ReleaseCandidatePackages.ps1` binds central versions, project metadata and TFMs, lock files, restore assets, generated nuspec dependency groups, strict package payloads, managed assembly references, internal dependency reachability, symbol policy, and repository/signature release blockers to `eng/pack/release-candidate-packages.json`. No dependency, public API, ModelFactory behavior, model Manifest, or model asset changed. / 阶段 35 将单包维护扩大为覆盖九个可打包项目的机器门禁，贯通中央版本、项目元数据/TFM、lock/assets、nuspec 依赖组、严格 payload、程序集引用、内部依赖闭包、符号策略及发布阻断；没有升级依赖或修改公共 API、ModelFactory、模型 Manifest 与模型资产。

## Mutation and consumer gates / 突变与 consumer 门

`eng/pack/Invoke-ReleaseCandidatePackageNegativeTests.ps1` generated disposable mutations and proved rejection of five independent faults: native runtime leakage, a wrong TFM, dependency-version drift, missing repository metadata, and an unexpected `tools` payload. `eng/pack/Invoke-CleanConsumerMatrix.ps1` stages source inputs in a disposable repository-shaped tree, force-evaluates only the copied lock files against the fresh local package containers, and verifies package provenance through the fresh NuGet cache metadata. Source clean-consumer projects and lock files are not rewritten. / 负向门分别拒绝 native 泄漏、错误 TFM、依赖版本漂移、缺 repository 元数据和意外 tools payload；consumer 矩阵在临时副本中更新容器哈希，原始项目和锁文件不被改写。

The 30-project package-only matrix reported 16 passed, 11 external-file skips, and three explicit external blockers (`visual-portable-detectors`, `visual-yolo-detection`, and `visual-yolo-multitask`), with no unexpected failure. Separate Llama graphs proved zero native package in the no-native assets and `DS-NATIVE-6001`, then proved caller ownership of `LLamaSharp.Backend.Cpu 0.27.0` and real exact-SHA CPU generation/embedding. No runtime evidence path was set. / 30 项纯包矩阵为 16 通过、11 个外部文件 skip、3 个显式 external blocker，且无意外失败；Llama 的无 native 与调用方 CPU 两张图分别验证诊断和真实执行，全程未设置 evidence 写入路径。

## Verification and blockers / 验证与阻断

Nine focused test projects passed `379/49/0` with the exact Qwen gate enabled; the environment-neutral full solution passed `378/50/0`. NuGet reported zero vulnerable and zero deprecated packages across the 18 solution projects and a separately restored 30-project clean-consumer solution. Outdated was retained without upgrades, including direct OpenVINO API/runtime and OpenCV API/runtime updates plus transitive updates. NuGet's solution/local-prerelease outdated path threw `Sequence contains no matching element`; Stage 35 therefore queried third-party updates per consumer against NuGet.org and kept internal `JYPPX.DeploySharp.*` version governance in the exact package gate. This tool limitation is not represented as a dependency finding. All nine packages returned the expected unsigned-package `NU3004`; symbol packages are intentionally not produced by the current baseline. `-RequireReleaseEligible` correctly rejected `dirty-worktree,unsigned-packages`. Signing, symbol/source policy approval, a clean committed tree, and explicit publication authority remain release blockers. / focused 与全量回归、18 个 solution 项目和 30 个 consumer 的漏洞/弃用审计全部通过；outdated 只报告不升级。本地 prerelease 源触发的 NuGet CLI 聚合异常被如实记录，第三方更新改为逐 consumer 查询 NuGet.org，内部包版本仍由精确全包门治理。九包均因未签名返回预期 `NU3004`，发布资格门正确拒绝脏工作树和未签名包。
