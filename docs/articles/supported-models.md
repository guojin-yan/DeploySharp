# Supported model roadmap / 支持模型路线表

## Stage 28 audio speech / 阶段 28 音频语音

Wav2Vec2 base-960h is the first executable audio profile. Its 16 kHz mono CTC waveform contract, fixed vocabulary, ONNX Runtime CPU graph, OpenVINO FP32 IR, OpenCV input factory, and NuGet-only consumer have matching local transcript evidence. The record remains External and is not `AlgorithmVerified`; the official catalog and downloadable assets remain empty. / Wav2Vec2 base-960h 是首个可执行音频 Profile。其 16 kHz 单声道 CTC 波形合同、固定词表、ORT CPU 图、OpenVINO FP32 IR、OpenCV 输入工厂和纯包 Consumer 具有一致的本机转写证据。记录仍为 External，非 `AlgorithmVerified`；官方 catalog 与可下载资产继续为空。

Whisper tiny.en is blocked without a complete Encoder/Prefill/KV Decode bundle, HuBERT base-ls960 without a downstream task head, and pyannote speaker-diarization 3.1 without an authorized complete gated bundle. See [the audio guide](visual-audio-speech.md), [acquisition guide](model-acquisition-audio-speech.md), [Stage 28 API changes](api-changes-stage28.md), and `eng/models/audio-speech/audio-speech-family-support.json`. / Whisper、HuBERT、pyannote 分别因完整三图、下游任务头和 gated 授权 bundle 缺失而阻断。详见[音频指南](visual-audio-speech.md)、[获取指南](model-acquisition-audio-speech.md)、[阶段 28 API 变更](api-changes-stage28.md)与支持矩阵。

## Stage 27 document intelligence / 阶段 27 文档智能

Official Donut CORD-v2 revision `8003d433...` is the executable single-page OCR-free structured-extraction representative. Its exact Processor/Tokenizer/Schema and three-role Encoder/Prefill/KV Decode bundle runs on ORT CPU and OpenVINO FP32 IR CPU through the real OpenCV source-page path, matching the official Predictor's 53 completion tokens, EOS, fields, and JSON. It remains External and not `AlgorithmVerified`; one observed run is diagnostic only. / 官方 Donut CORD-v2 是可执行单页 OCR-free 结构化抽取代表，双后端与官方 Predictor 同 Token/EOS/字段/JSON，但仍为 External、非 AlgorithmVerified。

LayoutLMv3 base is an official caller-OCR image/text/box contract only: it has no task head, the previously expected official FUNSD checkpoint was unavailable, and its CC-BY-NC-SA-4.0 terms block ordinary redistribution. Pix2Struct DocVQA retains the official dynamic 16x16 patch/row-column/T5 contract, but `use_cache=false` and no complete traceable native bundle was available. All three manifests are `redistributionAllowed:false`, outside the empty official catalog, with uploaded/downloadable both false. See [the guide](visual-document-understanding.md), [acquisition procedure](model-acquisition-document-understanding.md), [API changes](api-changes-stage27.md), and `eng/models/document-understanding/document-understanding-family-support.json`. / LayoutLMv3 与 Pix2Struct 保持精确 blocker；三份 Manifest 禁止再分发且不进入空 Catalog。

## Stage 26 native multimodal dialogue / 阶段 26 原生多模态对话

Official LLaVA OneVision Qwen2 0.5B now has an artifact-bound single-image Vision/projector, managed tokenizer/token embedding, empty-past Prefill, and named 24-layer KV Decode pipeline on ORT/OpenVINO CPU plus an OpenCV real-JPEG path. Official PyTorch/ORT 1.23.2 and current ORT 1.28.0/OpenVINO 2026.2.1 were compared on the same Prompt and authorized image; runtime-specific token/text drift is retained, so the model remains External and not `AlgorithmVerified`. / 官方 LLaVA OneVision Qwen2 0.5B 已具备工件绑定的单图 Vision/Projector、Managed Tokenizer/Embedding、Empty-past Prefill 与 24 层具名 KV Decode，并在 ORT/OpenVINO CPU 和 OpenCV 原图路径执行。同图同 Prompt 的 Runtime 差异被如实保留，因此仍为 External 且非 AlgorithmVerified。

Qwen2.5-VL 3B uses a Qwen Research checkpoint license and lacks a complete audited Vision-RoPE/projector/embedding/Prefill/KV ONNX/OpenVINO bundle. Phi-3.5 Vision is MIT but likewise lacks a complete audited HD processor/native bundle. Three manifests are `redistributionAllowed:false`, outside the empty catalog, with uploaded/downloadable both false. See [the guide](visual-native-multimodal.md), [acquisition procedure](model-acquisition-native-multimodal.md), and `eng/models/native-multimodal/native-multimodal-family-support.json`. / Qwen 与 Phi 均保持精确 blocker；三份 Manifest 禁止再分发、不进入空 Catalog，上传/下载均为 false。

## Stage 25 BLIP-family generation / 阶段 25 BLIP 模型族生成

The official predictor, independent PyTorch loop, ORT CPU, OpenVINO CPU, and OpenCV image path produced identical completion tokens, EOS, and text on the authorized image; encoder, selected-logit, and pixel goldens are gated. / 官方 BLIP Base Caption 双图绑定完整 Processor、Tokenizer、Prompt、生成、端口、容量、来源与工件 Identity，并在官方 Predictor、PyTorch 循环、ORT、OpenVINO 与 OpenCV 路径得到相同 Token、EOS 和文本，同时校验 Encoder/Logit/Pixel Golden。

BLIP VQA lacks a checkpoint SHA and complete question/answer/ranker native bundle. BLIP-2 OPT-2.7B and InstructBLIP Flan-T5-XL lack complete official Q-Former/projection/LLM/KV native bundles; InstructBLIP also carries research-only model restrictions. Four manifests remain External, `redistributionAllowed:false`, outside the empty official catalog, and not `AlgorithmVerified`. See [the guide](visual-generative-vision-language.md), [acquisition procedure](model-acquisition-blip-family.md), [all-stage inventory](development-model-inventory.md), and `eng/models/generative-vision-language/generative-vision-language-family-support.json`. / 其余路径保持精确 blocker；四份清单禁止再分发、不进入空目录且非 AlgorithmVerified。

## ModelFactory asset policy / ModelFactory 资产策略

- Prefer reproducibly exported portable ONNX and OpenVINO IR artifacts. TensorRT `.engine`/`.plan` remains device, CUDA, TensorRT and builder-version bound and is never a universal catalog asset. / 优先收录可复现导出的可移植 ONNX 与 OpenVINO IR；TensorRT `.engine`/`.plan` 与设备、CUDA、TensorRT 和 builder 版本绑定，绝不作为通用目录资产。
- Each accepted artifact records the upstream repository/release/commit, original checkpoint, exporter version and arguments, opset, tensor names/shapes, precision, size, SHA256, license, test image license, golden result and verified backends. / 每个准入工件必须记录上游仓库/Release/commit、原始 checkpoint、导出器版本与参数、opset、张量名称/形状、精度、大小、SHA256、许可证、测试图片许可证、黄金结果和已验证后端。
- The Ultralytics repository currently declares AGPL-3.0. Weight and dataset terms can differ. A model is not mirrored into a DeploySharp GitHub Release until its exact asset terms permit redistribution and the required notices/source obligations are prepared. / Ultralytics 仓库当前声明 AGPL-3.0；权重和数据集条款可能不同。只有精确资产条款允许再分发，且所需声明/源码义务已准备完成后，模型才能镜像到 DeploySharp GitHub Release。
- `E:\Model` is an authorized read-only validation source. Its 2026-08-06 inventory contains 176 ONNX files plus OpenVINO IR, checkpoints and device-bound engines. Local presence is not proof of provenance, license or catalog approval. / `E:\Model` 是获准使用的只读验证源；2026-08-06 清单包含 176 个 ONNX 及 OpenVINO IR、checkpoint 和设备绑定 engine。本机存在不代表来源、许可证或目录准入已通过。

The embedded official catalog remains empty until the first reviewed asset batch is explicitly published. Model support is added by family-sized complete stages, and every newly implemented deployment interface must add or update its row here and its ModelFactory admission record. / 在首批审核资产明确发布前，内置官方目录保持为空。模型支持按模型族规模的完整阶段加入；每个新部署接口都必须同步新增或更新本表行及 ModelFactory 准入记录。
