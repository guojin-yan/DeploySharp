# Visual.OpenCV Quick Start / Visual.OpenCV 快速开始

`JYPPX.DeploySharp.Visual.OpenCV` is the image-input adapter for DeploySharp Visual. It uses the official `JYPPX.OpenCV.CSharp.API` managed wrapper and produces a backend-neutral `PreparedVisualInput`; it does not reference OpenVINO, ONNX Runtime, or OpenCV DNN. / `JYPPX.DeploySharp.Visual.OpenCV` 是 DeploySharp Visual 的图像输入适配器。它使用官方 `JYPPX.OpenCV.CSharp.API` 托管包装器并生成与后端无关的 `PreparedVisualInput`，不引用 OpenVINO、ONNX Runtime 或 OpenCV DNN。

## Packages and native runtime / 包与 native runtime

Install the package together with `JYPPX.DeploySharp.Visual` and `JYPPX.DeploySharp.Core`. The current upstream wrapper is `5.0.0-preview.1`; it is a preview dependency, not a stable OpenCV release. / 安装本包以及 `JYPPX.DeploySharp.Visual` 和 `JYPPX.DeploySharp.Core`。当前上游包装器是 `5.0.0-preview.1`，它是 preview 依赖，不是 OpenCV 稳定发布版。

The DeploySharp package contains only managed wrapper references. On Windows x64, the verified native package is `JYPPX.OpenCV.runtime.win-x64 5.0.0-preview.1`; install it explicitly in the application. Do not copy native DLLs into a DeploySharp package. / DeploySharp 包只包含托管包装器引用。在 Windows x64 上，已核验的 native 包是 `JYPPX.OpenCV.runtime.win-x64 5.0.0-preview.1`，请由应用显式安装。不要把 native DLL 复制进 DeploySharp 包。

The wrapper currently targets `net46` through `net481`, `netcoreapp3.1`, and `net5.0` through `net10.0`. It has no `netstandard2.0` asset, so Visual.OpenCV publishes those 15 exact TFMs and does not claim `netstandard2.0`. / 包装器当前覆盖 `net46` 至 `net481`、`netcoreapp3.1` 以及 `net5.0` 至 `net10.0`，没有 `netstandard2.0` 资产。因此 Visual.OpenCV 发布这 15 个精确 TFM，不伪装支持 `netstandard2.0`。

The preview runtime is currently verified only for Windows x64. Linux, macOS, ARM, GPU and other RIDs are gated until the upstream runtime and a real runner are available. / 当前 preview runtime 仅核验 Windows x64。Linux、macOS、ARM、GPU 和其他 RID 在上游 runtime 与真实 runner 可用前均为 gated。

## Create a prepared input / 创建已准备输入

```csharp
var options = new OpenCvPreprocessOptions(
    new VisualSize(224, 224),
    resizeMode: OpenCvResizeMode.Letterbox,
    colorOrder: VisualColorOrder.Rgb,
    means: new[] { 123.675f, 116.28f, 103.53f },
    standardDeviations: new[] { 58.395f, 57.12f, 57.375f },
    layout: VisualTensorLayout.Nchw);

using PreparedVisualInput input = new OpenCvVisualInputFactory().CreateFromFile(
    Path.GetFullPath("image.jpg"), "images", options, cancellationToken: cancellationToken);
```

`FromFile` accepts an absolute regular file only. `FromStream` and `FromBytes` copy bounded encoded data and record a SHA256. Directories, reparse points, empty data and over-sized input are rejected before native decoding. / `FromFile` 只接受绝对普通文件。`FromStream` 和 `FromBytes` 会复制有大小边界的编码数据并记录 SHA256。目录、reparse point、空数据和超大输入会在 native 解码前拒绝。

`Resize`, `Letterbox`, and `CenterCrop` populate the existing reversible `ImageTransform`. RGB/BGR reorder, grayscale, alpha drop/composite/preserve, NCHW/NHWC/CHW/HWC, batch duplication, `Float32` normalization and `UInt8` output are validated by immutable options. / `Resize`、`Letterbox` 和 `CenterCrop` 会填充现有可逆 `ImageTransform`。不可变选项会校验 RGB/BGR 重排、灰度、alpha 丢弃/合成/保留、NCHW/NHWC/CHW/HWC、批次复制、`Float32` 归一化和 `UInt8` 输出。

The wrapper's verified `BGR2GRAY` operation is used for three-channel grayscale conversion. Other channel reorder and alpha composition are performed after a stride-aware copy into managed memory; no native `Mat`, pointer or span escapes the factory. / 对三通道灰度转换使用包装器已核验的 `BGR2GRAY` 操作。其他通道重排和 alpha 合成在按 stride 复制到托管内存后完成；native `Mat`、指针或 span 不会逃逸出工厂。

## Cancellation and diagnostics / 取消与诊断

OpenCV preprocessing is synchronous because the wrapper does not expose a cancellable image operation. Cancellation is observed before decode, before geometry, and at bounded row boundaries; cancellation during one native call is reported when control returns. / OpenCV 预处理是同步的，因为包装器没有可取消图像操作。取消会在解码前、几何变换前以及有界行边界检查；native 调用期间的取消会在控制权返回后报告。

Stable errors are `DS-OPENCV-5201` through `DS-OPENCV-5207`. `OpenCvRuntimePreflight.Check()` verifies the managed/native ABI before decoding and maps missing DLL, architecture, entry-point and version errors to `DS-OPENCV-5204` while retaining the inner exception. / 稳定错误码为 `DS-OPENCV-5201` 至 `DS-OPENCV-5207`。`OpenCvRuntimePreflight.Check()` 在解码前验证 managed/native ABI，并将 DLL 缺失、架构、入口点和版本错误映射为 `DS-OPENCV-5204`，同时保留 inner exception。

The small PNG fixtures under `tests/assets/opencv` are deterministic Apache-2.0 contract data generated by `eng/test-models/Generate-OpenCvFixtures.ps1`. They are not algorithm models, catalog entries or Release assets. / `tests/assets/opencv` 下的小型 PNG 是由 `eng/test-models/Generate-OpenCvFixtures.ps1` 生成的确定性 Apache-2.0 合同数据，不是算法模型、目录条目或 Release 资产。
