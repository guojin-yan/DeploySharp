# Multimodal and OpenCV DNN / 多模态与 OpenCV DNN

`JYPPX.DeploySharp.Multimodal` is the backend-neutral orchestration package. It owns ordered encoded-media identity, optional regions, request validation, capability probes, single-writer sessions, timeout/cancellation mapping, completed results, and contiguous terminal streams. Core continues to own canonical result DTOs; vendor-native handles and image objects do not enter the public contract. / `JYPPX.DeploySharp.Multimodal` 是后端中立编排包，负责有序编码媒体身份、可选区域、请求校验、能力探测、单写入会话、超时/取消映射、完整结果和连续终止流。Core 继续持有规范结果 DTO；厂商 native 句柄与图像对象不进入公共合同。

The included Visual-native adapter currently accepts one whole image because that is the proven Visual contract. `ExternalMultimodalProbes` reports `llamasharp-mtmd` and OpenVINO GenAI VLM as unavailable with stable reasons until an application supplies an exact licensed native/model/tokenizer bundle. A probe is evidence of an explicit boundary, not runtime support. / 内置 Visual-native 适配器当前只接受一张完整图像，因为这是已验证的 Visual 合同。应用提供精确且许可明确的 native/model/tokenizer bundle 前，`ExternalMultimodalProbes` 会以稳定原因将 `llamasharp-mtmd` 与 OpenVINO GenAI VLM 报告为 unavailable。能力探测只证明边界明确，不代表运行时已支持。

`JYPPX.DeploySharp.Backend.OpenCV` is separate from `JYPPX.DeploySharp.Visual.OpenCV`. The Visual package decodes and preprocesses pixels; the backend package loads a caller-owned ONNX artifact through OpenCV DNN and implements Core `IBackendProvider`/`IInferenceSession`. The first preview contract supports CPU, one static NCHW float32 image input with batch 1, and static float32 outputs. Input/output names and shapes are declared explicitly because the upstream API is not used as an ONNX schema parser. / `JYPPX.DeploySharp.Backend.OpenCV` 与 `JYPPX.DeploySharp.Visual.OpenCV` 相互独立。Visual 包负责像素解码和前处理；后端包通过 OpenCV DNN 加载调用方持有的 ONNX 工件并实现 Core `IBackendProvider`/`IInferenceSession`。首版 preview 合同支持 CPU、一个静态 batch 1 NCHW float32 图像输入和静态 float32 输出。输入/输出名称与形状必须显式声明，因为上游 API 不作为 ONNX schema parser 使用。

The pinned smoke model is `tests/assets/onnxruntime/classification.onnx`, 297 bytes, SHA-256 `05a885298cca6e04b83732a46ff340f48203cc62e5fa89af74fe3eeab259de2a`. It performs `ReduceMean` over spatial axes and produces the auditable golden `[2.5, 6.5, 10.5]`. Tests also cover hash drift, invalid names/shapes, unsupported devices, cancellation, disposal, package-only restore, and real native execution on Windows x64 CPU. / 固定 smoke 模型为 `tests/assets/onnxruntime/classification.onnx`，297 字节，SHA-256 如上；它在空间轴执行 `ReduceMean`，可审计 golden 为 `[2.5, 6.5, 10.5]`。测试还覆盖 hash 漂移、错误名称/shape、不支持设备、取消、释放、纯包还原以及 Windows x64 CPU 真实 native 执行。

Dynamic shapes, implicit preprocessing, multi-input models, non-float outputs, GPU/NPU targets, Linux/macOS native execution, and general ONNX operator coverage are not claimed. Applications must install a matching `JYPPX.OpenCV.runtime.*` package and must keep model/runtime redistribution decisions outside DeploySharp. / 当前不宣称动态 shape、隐式前处理、多输入模型、非 float 输出、GPU/NPU target、Linux/macOS native 执行或通用 ONNX 算子覆盖。应用必须安装匹配的 `JYPPX.OpenCV.runtime.*` 包，并在 DeploySharp 之外自行决定模型/运行时再分发。
