# OCR Orientation and Automatic Correction / OCR 方向分类与自动纠正

## Scope / 范围

The orientation slice adds a backend-neutral four-class classifier before the existing OCR detector and recognizer. The stable angle semantics are clockwise correction angles `0`, `90`, `180`, and `270` degrees. The image origin is the top-left and width/height are exchanged for quarter turns. / 方向切片在现有 OCR 检测器和识别器之前增加后端无关四分类模型。角度语义是顺时针纠正角 `0`、`90`、`180`、`270` 度，图像原点在左上角，四分之一旋转交换宽高。

`OcrOrientationSchema` requires the output name, rank/shape, element type, value semantics, and explicit class mapping. A model with `[1,4]` logits is not allowed to silently mean a particular angle order. `OcrOrientationDecoder` applies stable highest-score selection and lowest class-index tie breaking. Rejection returns `Rejected`; callers must choose a policy instead of assuming upright text. / `OcrOrientationSchema` 要求输出名称、rank/shape、元素类型、数值语义和显式类别映射。`[1,4]` logits 不允许静默代表某个角度顺序。`OcrOrientationDecoder` 使用确定性最高分和最低类别索引同分规则。拒绝结果为 `Rejected`，调用方必须显式选择策略。

## OpenCV path / OpenCV 路径

`OpenCvOcrImageInputFactory.CreateOrientationInput` decodes once. `OcrOrientationWorkflow` runs the classifier, invokes `CreateOriented`, and sends the new image input to the existing `OcrPipeline`. Native `Mat` and runtime handles do not enter Visual public APIs. / `OpenCvOcrImageInputFactory.CreateOrientationInput` 只解码一次。`OcrOrientationWorkflow` 运行分类器，调用 `CreateOriented`，再把新图像输入交给既有 `OcrPipeline`。native `Mat` 和运行时句柄不会进入 Visual 公共 API。

After recognition, the workflow applies the inverse right-angle transform to every authoritative polygon. The returned region geometry and `SourceSize` use original-image coordinates, `CorrectedSourceSize` records the detector/recognizer image, and list order remains the upright reading order. / 识别完成后，工作流对每个权威 polygon 应用直角逆变换；返回区域几何与 `SourceSize` 使用原图坐标，`CorrectedSourceSize` 记录检测/识别图尺寸，列表顺序继续保持纠正后的正常阅读顺序。

The preview fixture uses `text-orientation.onnx` and its OpenVINO IR conversion. It is generated by `eng/test-models/Generate-OnnxRuntimeFixtures.py` with `onnx==1.22.0` and by `Generate-OpenVinoFixtures.py` with OpenVINO `2026.2.1`; both are Apache-2.0 DeploySharp contract fixtures, not official OCR algorithm models. / Preview 夹具使用 `text-orientation.onnx` 及对应 OpenVINO IR 转换，由 `onnx==1.22.0` 和 OpenVINO `2026.2.1` 生成；两者均为 Apache-2.0 DeploySharp 契约夹具，不是正式 OCR 算法模型。

## Fidelity and performance / 保真与性能

Production algorithm support requires `AlgorithmVerified` evidence for category order, resize/color/normalize, threshold calibration, rotation direction, OCR detector/recognizer semantics, golden tensors and P50/P95. The preview tests prove named tensor contracts, CPU ONNX/IR execution, one native rotation, OCR provenance, cancellation, and owned disposal only. / 正式算法支持需要类别顺序、resize/color/normalize、阈值校准、旋转方向、OCR 检测/识别语义、黄金张量和 P50/P95 的 `AlgorithmVerified` 证据。Preview 测试只证明命名张量契约、CPU ONNX/IR 执行、一次 native 旋转、OCR 来源、取消和资源所有权。
