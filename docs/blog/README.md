# DeploySharp 博客文章

这里保存作者围绕 DeploySharp 撰写、用于博客等平台发表的 Markdown 主稿和配图。文章按所依据的库版本、写作年月归档；已发表文章在对应版本索引中登记平台、日期和链接。

| 基于版本 | 系列入口 | 当前状态 |
| --- | --- | --- |
| 2.0.0 | [2.0.0 系列](2.0.0/README.md) | 第 01 篇已完成项目介绍、特色展示、模块导览与优势说明；其余主题按计划撰写，尚未向博客平台发表 |

## 目录与命名

```text
blog/
  README.md
  2.0.0/
    README.md
    YYYY-MM/
      YYYY-MM-DD-NN-article-slug.md
      assets/
        NN-article-slug/
```

`YYYY-MM-DD` 使用主稿实际创建日期，`NN` 为系列编号，`article-slug` 为稳定的英文主题名。图片随文章所在月份保存，按文章编号和主题分目录；正文使用相对路径引用。正文及配图在开始写作时创建，不预建空文件。

文章后续修订保留原文件名，在文首登记修订日期。面向新库版本的教程放入新版本目录，并注明与旧文的关系。

## 主稿与发表记录

每篇正文保留一个主稿，文首简要登记基于版本、源码 Tag、创建日期和修订日期。跨平台发表可以调整摘要、目录和图片链接，代码、版本、测试条件与结论应与主稿一致。

博客正文中的资源网址使用代码块或行内代码展示完整 URL，方便读者在不支持点击链接的平台复制使用。图片保留 Markdown 图片引用；仓库中的文章索引继续使用正常导航链接。

发布总览的项目简介应简洁说明项目定位、主要引擎、任务范围和开源信息，并就近提供源码与包获取地址。软件获取章节提供实际使用入口；后续教程放在结尾按场景引出。

各版本索引分别记录正文状态和实际发表记录。只有真实发表后才填写平台、日期和 URL；同一篇文章可登记多行平台记录。引用博客平台图片地址时保留本地原图，便于迁移与修订。

[使用指南](../articles/index.md)提供当前操作说明，[版本说明](../releases/README.md)记录交付范围。博客正文以完整场景讲解，并注明其适用版本；后端支持结论仍需核对[模型与后端验证矩阵](../model-backend-verification-matrix.md)。
