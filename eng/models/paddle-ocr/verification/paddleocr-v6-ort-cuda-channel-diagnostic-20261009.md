# PP-OCRv6 ORT CUDA 多推理通道诊断（2026-10-09）

这是一项针对完整 `det → crop/batch → rec → merge` 流程的 Session 池诊断。它在同一张密集 HierText 页面上分别使用 1、2、4 个独立分类/识别阶段 Session，每个组合运行三轮 `5 warm-up + 50 measured`，batch 为 16。为了观察 CUDA 浮点漂移，诊断显式启用了 `DEPLOYSHARP_PADDLEOCR_ALLOW_NUMERIC_CONTRACT_DRIFT=1`；因此本记录不是发布性能门，也不改变生产默认通道数。严格、未放宽的参考结果见[默认区域上限正式记录](paddleocr-v6-medium-default-region-limit-20261009.md)。

## 合同与硬件边界

- 27/27 行完成，文本 SHA 和语义合同 SHA 均稳定；Medium 的完整浮点合同出现 1、2 或 3 个变体，最大绝对漂移 `2.28047371e-4`。这解释了为什么严格门会拒绝部分重复运行，但不等同于精度通过或可以默认放宽合同。
- `nvidia-smi` 只在每个进程前后采样：P0、图形/SM `1425 MHz`，最大图形时钟 `2100 MHz`，功耗约 `25.91–26.38 W`，利用率 `2–5%`，温度 `53–57°C`。没有锁频，也没有连续遥测，不能宣称硬件极限。
- 这是单主机、单页面、v6 三档和 ORT CUDA 的调度诊断。没有覆盖 TensorRT/OpenVINO/OpenCV、其它模型版本、跨设备吞吐、长时间 soak 或准确率/CER/WER。
