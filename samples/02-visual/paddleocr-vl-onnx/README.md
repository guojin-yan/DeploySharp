# PaddleOCR-VL ONNX CPU example

This example runs the experimental PaddleOCR-VL-1.6 four-graph bundle through the production C# `PaddleOcrVlOnnxSession` and ONNX Runtime CPU backend. It prints the raw generated text, token count, termination reason and generation time.

The sample's six-argument mode intentionally accepts a prepared little-endian `float32` patch file. The file must be generated by the pinned official PaddleOCR-VL Processor and contain the exact `[grid_h, grid_w, 3, 14, 14]` RGB-normalized tensor for one image. The production Visual package also exposes `PaddleOcrVlImageProcessor` for packed RGB bytes; applications that reference `JYPPX.DeploySharp.Visual.OpenCV` can use `OpenCvPaddleOcrVlInputFactory.CreateFromFile` or `CreateFromBytes` to decode an image once and construct the same official patch tensor automatically. This sample keeps the raw-patch mode because it does not require an OpenCV native runtime.

The four graph files must be one matching export set: `vision.onnx`, `embedding.onnx`, `decoder.onnx` and `head.onnx`. The tokenizer directory must contain the pinned official `tokenizer.model`, `tokenizer.json`, `tokenizer_config.json` and `chat_template.jinja`. The `models-paddleocr` Release now distributes these eight files plus `paddleocr-vl-bundle.json` as independent assets. `PaddleOcrReleaseClient.GetBundleAsync("paddleocr-vl/1.6")` downloads and verifies the nine files, then maps their globally unique Release names to the local names expected by `PaddleOcrVlOnnxSession.CreateVerified`.

```powershell
dotnet run --project samples/02-visual/paddleocr-vl-onnx/PaddleOcrVlOnnx.csproj -c Release -- `
  E:\Model\PaddleOCR-VL\1.6\c5630abae1d940eafe0697512a0325494b02ab42 `
  E:\Model\PaddleOCR-VL\exports\dynamic-fp32-20261023 `
  E:\Model\PaddleOCR-VL\inputs\ocr-demo-1-pixel_values.bin `
  672 448 TextRecognition
```

The checked-in [Linux ORT evidence](../../../eng/models/paddle-ocr/verification/paddleocr-vl-managed-csharp-ort-linux-20261024.json) covers six fixed real images and all six supported task prompts. The [managed RGB evidence](../../../eng/models/paddle-ocr/verification/paddleocr-vl-managed-processor-parity-20261024.md) also verifies automatic resize, normalization and patch packing. [Linux OpenVINO CPU](../../../eng/models/paddle-ocr/verification/paddleocr-vl-openvino-linux-20261024.md) completed the same six tasks with the documented memory settings. These are correctness records, not performance rankings or memory stability guarantees.

The [document example](../paddleocr-vl-document/README.md) adds image decoding, manual/detected regions, decoded-page reuse, multi-page execution and JSON/Markdown export. OTSL logical tables/HTML and Spotting source/page polygons are implemented; mixed-task pages can optionally use geometric XY-cut reading order while retaining original region indices. Independent quality evaluation, other task semantics, table pixel cell boxes, Windows VL, full CUDA/TensorRT/OpenCV DNN inference and formal performance remain open. The [RTX2060 CUDA run](../../../eng/models/paddle-ocr/verification/paddleocr-vl-cuda-head-group-20261024.md) passed only some tasks and still failed Spotting due to memory allocation; it does not establish full GPU support. The VL Bundle is now available in the `models-paddleocr` catalog, with the backend and quality limits above unchanged.
